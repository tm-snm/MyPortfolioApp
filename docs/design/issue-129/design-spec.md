## 1. この仕様書で決める範囲

全主要画面で共通に使う配色・文字・余白・レイアウト・部品・状態表現を整理する。
アプリへの適用は#130。#129ではアプリコード・DBを変更しない。
生成画像は方向性の参考とし、画像内の細かな文字・色・寸法をそのまま実装の正解とは扱わない。

## 2. デザインの基本方針

- 「つまずきを気軽に残し、後から探して再利用する」学習ツール。
- 面は白、背景は低彩度グレー、青は主操作と現在地に使う。
- 本文と操作の優先順位をつけ、すべてを同じ強さの色・枠・影で囲まない。
- 情報や機能を削除する判断と、見た目を統一する判断を分ける。
- 既存Rails／ERB／Bootstrap／Turbo／Stimulus／importmapを維持する。

## 4. 文字

| 項目 | 提案値 | 補足 |
|---|---|---|
| フォント | OS標準の日本語ゴシックを基本 | system-ui、Segoe UI、Hiragino Kaku Gothic ProN、Yu Gothic、Meiryo、sans-serif等。外部配信は前提にしない |
| 本文 | 16px、行高1.7 | rem等で拡大可能にする |
| ページ見出し | PC32px／狭い画面24px、太字 | 1画面の主見出しを明確に |
| セクション見出し | 20〜24px | 文書構造に沿ってh2/h3を使う |
| 一覧タイトル | 18px、太字 | 長い日本語は折り返す。重要な文字を安易に省略しない |
| ラベル・補足・状態 | 14px以上 | 必須／任意や日付を読める大きさに |
| コード | 14px以上、等幅 | 長い行はコード領域内で横スクロール |

本文の横幅は最大約720pxを目安にし、広いPC画面でも行が長くなり過ぎないようにする。
文字を小さくして情報を詰め込まない。長文と200%拡大は#142/#146で検証する。

## 5. 余白・角丸・境界・影

- 余白単位: 4、8、12、16、24、32、48px。
- ボタン間: 8〜12px。フォーム項目間: 16〜24px。主要セクション間: 24〜32px。
- 面・一覧グループの角丸: 8px。ボタン・入力欄: 6px。
- ボーダー: 原則1px。エラー欄は2px程度と文字説明を併用。
- 影: 原則なし〜ごく薄い影。ナビの現在地や情報の階層を影だけで表現しない。
- 一覧は同じ行構造をそろえる。各要素をさらにカードで囲む重ね構造は避ける。
- タップ／クリック操作領域は原則44px以上を設計目標とする。静的バッジまで一律44px高にしない。

## 6. 画面の共通レイアウト案

| 幅 | ナビ | 主要領域 |
|---|---|---|
| 1200px以上 | 左ナビ、幅224px程度 | 左右余白32px。本文と補助領域を横並びにできる |
| 768〜1199px | 上部ヘッダー＋開閉メニュー | 左右余白24px。本文・補助操作は縦積みを基本 |
| 768px未満 | 上部ヘッダー＋「メニュー」 | 左右余白16px。1列、長いボタン文字は折返し |

Bootstrapの既存区切りを使う想定で、新しい基盤を導入しない。
PC詳細の目安は本文最大720px＋補助領域約280px＋間隔24px。確保できなければ縦積みにし、本文を押しつぶさない。
固定幅の合計で小さな画面をはみ出させない。ウィンドウ幅と文字拡大に追従する。
公開トップ・認証・公開情報ページには左ナビを強制せず、上部ヘッダーと読みやすい幅で共通の色・部品を使う。
フッターの利用規約・プライバシーポリシー・お問い合わせを維持する。

## 7. ナビゲーション

- ログイン後の基本項目: カード一覧、今日の復習、プロンプト、ダッシュボード。
- 「カードを作成」は主要操作として分ける。PC左ナビと同じ場所に同一CTAを何度も置かない。
- 現在地は文字・背景・線などで示し、意味に合う場合はaria-currentを使用する。
- アカウント削除とログアウトはアカウント領域にまとめる方向を共通案とする。
- 未ログイン: アプリ名、ログイン、新規登録。トップの主CTAは選定案の「無料で始める」。
- モバイルの開閉は既存Bootstrap collapseを活かす案。開閉ボタンに意味のあるラベルとaria-expanded/controlsを持たせる。
- メニューを閉じたときは開いたボタンへ戻れるようにする。リンク遷移後のフォーカスは遷移先の本文を優先する。
- アイコンは補助。ラベルだけでも理解できるようにし、新しいアイコン用Gem/npmを勝手に追加しない。

具体的な並び替えや表示項目の削除は#137、文言の詳細は#141で整合させる。
このナビ変更を理由にroutes・認証・所有者スコープを変えない。

## 8. 共通部品

### 8.1 ボタンとリンク

| 種類 | 表現 | 用途 |
|---|---|---|
| 主操作 | 青塗り＋白文字 | 保存、検索など、その場で進めたい操作 |
| 副操作 | 白または透明＋青文字・枠 | 戻る、編集など |
| 補助リンク | 文中リンク、判別できる下線 | 詳しい説明、関連画面 |
| 危険操作 | 赤系の文字・枠 | 削除・退会。必要な既存確認を維持 |

- 同じ操作名・色の役割を画面間でそろえる。1画面に必ず1個だけ、という機械的な制限にはしない。
- 操作するbutton、遷移するlinkの意味を維持する。リンク風の見た目で誤解させない。
- hover／active／focus／disabled／送信中を定義する。無効化を薄い色だけで伝えない。
- 送信中は「保存中...」「解析中...」「コピー中...」等の具体的な文言を使用する。

### 8.2 フォーム

- 入力欄の上に可視ラベル。placeholderだけで項目の意味を伝えない。
- 必須／任意は現行validationに合わせる。UIを簡単にするために必須条件を変えない。
- 文字・余白・枠・説明・エラーの位置をそろえる。
- エラーは欄の近くと必要な要約に表示し、aria-invalid／aria-describedbyを維持する。
- 入力値・タグを保持し、エラーから修正できる。閉じたパネルにエラーがあれば見える状態にする。
- 閉じた入力をdisabledにして送信対象から外さない。値のクリアや再解析の上書き範囲は#136で決める。
- フォームを開閉するだけでDB更新・保存・復習完了を発生させない。

### 8.3 タグと状態ラベル

- タグはニュートラルな淡い背景＋濃い文字。選択中と候補を区別する。
- 解除操作には「Dockerを選択から外す」等の名前を付ける。長いタグは折り返す。
- 理解度・重要度・復習予定は項目名と値を表示する。色だけに依存しない。
- 一覧の理解度・重要度は今回の選定画像にあるため、現段階で削除しない。
- 「通常」「未設定」「復習日未設定」を同じ意味にしない。状態の意味は既存Modelを正とする。
- 重要度高は低彩度赤、中は琥珀、低／未設定はグレー等を候補にする。エラーと混同しないよう文言を必ず付ける。

### 8.4 開閉パネル

- 見出しと開閉状態を示し、キーボードで開閉できる。
- 本文そのものをむやみに閉じない。項目名は「絞り込み」「復習を記録」等と具体化する。
- どの項目を最初から開くか、閉じた後の値の保持等は担当Issueで確定する。
- モーダル・新しいウィザードを共通仕様として追加しない。

| 検索0件 | 条件に一致しないことと、解除・変更手段を表示 | #138 |

| 送信中 | 具体的な文言と必要な一時無効化。入力値と送信先を維持 | #143 |

### フォーカス案

- 青#2457D6の3pxリング、2pxの間隔を基本とする。
- 青いボタン上では白い間隔を挟むなど、背景に埋もれない表現にする。
- キーボード操作時のフォーカスを消さず、表示領域の外へ隠さない。
- 動きは短く控えめにし、動きを減らす設定に対応する。
- この仕様案だけでアクセシビリティ適合済みとは判断しない。

## 11. 大まかなコア導線

テンプレート選択 → コピー → 外部AIで整理 → 回答貼付 → 解析結果の確認・編集 → 保存 → 詳細 → 検索・復習で再利用。

- 回答をすでに持つ人は既存のカード作成画面へ直接進める。
- 外部AIとの往復を、アプリ内部のAI処理のように見せない。
- 解析は未保存、保存は本人による明示操作を維持する。
- 復習記録は既存の次回日必須条件を維持する。
- ここでは新しい画面統合・自動保存・直接コピー・日付補助の採否を決めない。
