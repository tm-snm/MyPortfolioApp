# BAハイブリッド案とUX見直し計画

作成日: 2026-11-02
Issue #129の追加検討。アプリへの適用は未実施。
ユーザーの希望: **Bの構成を基本とし、色味・色彩にはAを採用する。**
この基本方針と、以下の追加UX変更の承認は分けて扱う。最終仕様はまだ確定していない。

## 1. 新しいデザイン案

[BAハイブリッド画像（6画面）](images/concepts/BA-hybrid-workspace.png)

- Bから採用: PC左ナビ、簡潔な一覧、本文と補助操作の分離、モバイルの縦積み。
- Aから採用: ページ#FAF9F5、面#FFFFFF、主要色#28644C、本文#24382D、補足#58665D、境界#D8DED5。
- 形・密度はBを基本とし、ボタン8px程度、過大な影を避ける。Aの横ヘッダーへは変更しない。
- 緑は主要操作・選択中・復習予定を示すために使い、画面全体を緑で塗らない。
- 理解度・重要度はニュートラルな文字中心。色だけで状態を示さない。
- 日付は作成日／復習日をラベルで区別する。すべての状態を同じ強さのバッジにしない。
- 本文16px、行高約1.7、モバイル操作領域44px以上を設計目標とする。

トップ・一覧・詳細のPC／モバイルを1枚にまとめた概念画像。画像内の縮小文字・寸法は実装仕様ではない。
PC詳細は「復習パネルを開いた状態」の見本になっているが、通常の閲覧時は閉じる案を推奨する。
画像で省略されていても、復習後の理解度、未来のメモ、フッター、編集・出力・削除等を機能から削除しない。
一覧で理解度・重要度を省略することは新しいUX提案であり、データ削除・機能廃止ではない。

## 2. 根拠と制限

前回撮影した現行画面16枚を記録した[current-state.md](current-state.md)と、今回再確認したView・Specを根拠にした計画。
新しいブラウザ監査・ユーザーテストは行っていない。操作時間や離脱率への効果は仮説であり未計測。
今回再確認: カード通常フォーム・AI解析フォーム・作成ステップ・復習フォーム・学習状態フォーム・テンプレート一覧／詳細、関連Request/Service Spec。
未撮影の認証・ダッシュボード・アカウント・公開情報ページの「見づらさ」は断定せず、共通ルールと今後の確認対象として示す。

## 3. 各操作の現状と修正案

| 操作 | 現在の問題・負担 | 推奨案 | 減る負担／維持する条件 |
|---|---|---|---|
| 初回利用 | カード0件でも大きな検索フォームが先。トップの主ボタンは説明への移動 | トップの「無料で始める」、カード0件時は「最初のカードを作る」→テンプレート選択を主導線に | 初回に使えない検索条件の確認を省く。ログイン後の通常一覧を常に案内ページへ置き換えない |
| テンプレート選択 | 空のお気に入り／履歴が用途選択より上。詳細のコピーは長い本文の下 | 初回は用途別テンプレートを先に。お気に入り・履歴はデータがある場合に強調。詳細は上部にコピー、本文は開閉可能 | スクロールを減らす。コピー失敗時は本文を開いて手動コピーできる |
| 外部AIへの移動 | 他アプリとの往復自体は必要。戻った後の次操作を探す | コピー後に「外部AIで整形→回答をコピー→回答を貼り付ける」を短く表示。既存貼付画面へ直接リンク | 外部AI操作をなくしたように見せない。AI APIは追加しない |
| カード作成への入口 | AI回答をすでに持つ人へテンプレート選択を強制すると遠回りになる | 通常の「カードを作成」は既存貼付画面へ直行。そこに「テンプレートが必要な方はこちら」を副導線として置く | 新しい作成方法選択ページやモーダルを挟まない。手入力作成への副リンクも検討 |
| AI出力の確認・保存 | 原文・編集欄・Markdown表示が縦に3重。保存が遠い。再解析と保存の意味が混同しやすい | 解析後はタイトル／本文の編集を中心に。原文と「解析時点の表示」は閉じて開ける。保存を主ボタンにし、再解析は原文の領域へ | 保存前確認は残す。原文も送信・保持する。再解析は編集内容を置き換える旨を明示 |
| 任意のメモ・タグ | 候補なし等の補足で画面が長くなる | 抽出済みメモ・選択済みタグは見せる。空メモは「メモを追加（任意）」、タグ候補は必要時に表示 | 既存値は隠して失わせない。エラーのある領域は自動で開く |
| カード検索 | 5条件を毎回表示。結果を見るまでに縦長 | 検索欄＋検索を常時表示。他条件は「絞り込み」。使用中の条件と解除を常時見せる | 通常検索の操作は維持。条件を閉じても入力・GET URL・並び順を保持 |
| カード詳細の閲覧 | 本文より前に複数の更新フォーム | 本文→未来のメモを優先。PCは右補助領域、モバイルは本文後の操作 | 読む前に更新フォームを通らずに済む。読みたい情報まで折りたたまない |
| 学習状態の変更 | 読むだけでも選択欄と更新ボタンが出る | 現在の理解度・重要度を短く表示。「学習状態を変更」でフォームを開く | 編集したいときは開く操作が1回増える代わりに通常閲覧を簡潔にする |
| 復習 | 日付の変更・復習記録・解除が同時に並ぶ。理解度の入力も別フォームと重複する | 「復習を記録」と「予定を変更」を分けて開く。記録時は既存の理解度欄も同じフォームで使う | 復習時は別途「学習状態を更新」しなくてよい。次回復習日は必須のまま |
| Markdown出力・復習プロンプト | 本文後に複数の副操作が並ぶ | 「その他の操作」に集約し、項目名は具体的に維持 | 頻度の低い操作の常時表示を減らす。出力は既存GET、復習プロンプトのコピーも維持 |
| 削除・アカウント | 退会が日常のナビと同列。誤操作の懸念 | カード削除は補助メニュー内、退会・ログアウトはアカウント領域へ | 削除確認・再認証・CSRF・認可を省略しない |

操作をすべて折りたたむ方針ではない。検索・保存など頻度が高い操作、本文、エラー、選択中の状態は見せる。

## 4. 変更前後のコアフロー

### 作成（初回）

現在: ログイン→空の一覧で検索フォームを通過→テンプレート一覧→詳細→本文下まで移動→コピー→外部AI→貼付→解析→長い原文・編集・表示を確認→保存。

推奨: ログイン→初回の作成案内→用途選択→上部でコピー→外部AI→貼付→編集を確認→保存。

ページ数は上部コピーや折りたたみだけでは減らない。主にスクロール量と選択肢の数を減らす。

### 作成（整形済みAI回答がある場合）

カードを作成→回答を貼付→内容を確認→必要な編集→保存。
テンプレート選択は必須にしない。解析と保存は別操作のままにする。

### 検索・再利用

一覧→キーワード検索（必要時だけ条件を開く）→カードを開く→本文を読む。
検索候補は入力補助であり、候補選択だけで勝手に詳細へ移動させない。
一覧へ戻る際の検索条件復元は別途検討候補とし、任意の戻りURLを無検証で受け付けない。

### 復習

今日の復習→カード本文を読む→「復習を記録」を開く→次回日・必要なら理解度を選ぶ→「復習した」。
予定だけを変える操作と、復習した事実を記録する操作を混ぜない。
通常状態のカードでは、現行仕様どおりまず復習日を設定する。今回の表示変更で新しい状態遷移を作らない。

## 5. 画面ごとの必要最小限の情報

| 画面 | 最初から見せる | 必要時に開く／移す |
|---|---|---|
| トップ | 何ができるか、具体例1つ、利用開始・ログイン、簡潔な3段階説明 | 詳しい使い方は下へ。長い機能一覧は置かない |
| 初回のカード一覧 | 最初の作成案内、作成ボタン | カードのない状態では検索条件を主役にしない |
| 通常のカード一覧 | タイトル、日付、関連する復習予定、検索、作成 | 理解度・重要度は詳細へ、追加検索条件は開閉 |
| 復習絞込中の一覧 | タイトル、復習日／期限超過、現在の条件 | 作成日は副情報へ。復習の判断に不要なバッジを減らす |
| テンプレート一覧 | 用途・短い説明・選択操作、公式／個人の区別 | 履歴がないときの大きな空パネルは省略。CRUD・お気に入りは副操作 |
| テンプレート詳細 | 用途、コピー、外部AIでの次操作 | プロンプト全文、編集・削除等の管理操作 |
| AI貼付前 | 貼付欄、内容を確認、形式崩れ時も編集可能な説明 | 長い4ステップは「現在のステップ＋全体を見る」へ。テンプレート／手入力は副導線 |
| AI解析後 | タイトル、本文、既存メモ／選択タグ、保存 | 元のAI出力、再解析、解析時点表示、未使用の任意項目 |
| カード詳細 | タイトル、タグ、本文、未来のメモ、短い学習・復習状態、戻る | 復習・予定変更・学習状態変更・出力・削除 |
| カード編集 | 既存タイトル・本文・メモ・タグ、更新、詳細へ戻る | 作成時専用の説明は出さない |
| 認証 | 必須入力、エラー、ログイン／登録／復旧の導線 | アプリ紹介の繰返しを増やさない。Google認証は出さない |
| ダッシュボード | 未撮影のため配置評価は保留。全数値の優先度とカード／復習への導線を確認する計画 | 集計仕様を変えたり新しい統計を追加したりしない |
| アカウント・公開情報 | 退会に必要な影響説明・確認、規約等の本文と戻り先 | 重要な退会説明や規約本文を「最小情報」の名目で削らない |

## 6. 追加で比較したい案（未採用）

| 候補 | 期待する利点 | 採用前に確認すること |
|---|---|---|
| お気に入り／最近使ったテンプレートから直接コピー | 詳細画面への移動を1回減らせる | 本文の安全な取得・表示、JSなしの詳細リンク、認可、コピー失敗、履歴更新。一覧へ全テンプレート本文を無条件に詰め込まない |
| 復習日の「明日」「1週間後」等の入力補助 | カレンダー操作を減らせる | 日付を選ぶ補助だけに限定し、選択後に本人が送信。自動復習間隔・次回日の自動決定とは分ける |
| 検索条件を保った「一覧へ戻る」 | 毎回検索し直す負担を減らせる | 既存クエリの許可範囲・安全な戻り先・Turbo履歴、スマートフォンの戻る操作 |
| タイトル／日付等でカードを開きやすくする | 小さな「詳細を見る」を探す負担を減らせる | タイトルリンクを主にし、キーボード操作可能に。行内の別ボタンとクリック領域を衝突させない |

これらは表示整理以上の振る舞いの変更を含むため、#130に含められるかをIssueと照合して合意する。必要なら別Issueへ分ける。今回実装しない。

現段階で推奨しない案:
- 全画面を1つの巨大フォームへ統合: 外部AIとの往復は消えず、保存・再解析の責務と入力保持が複雑になる。
- 貼付直後の自動保存: 解析の誤りを修正する機会を失う。
- 日付なしの「復習完了」: 既存validationと意味が変わる。
- 入力ごとの自動検索: 通信・日本語変換・画面更新を増やすため、まず明示的な検索を維持する。
- すべての補助情報の削除: 初めて使う人やエラーから復帰する人が困る。必要時に参照可能にする。

## 7. 進める順序

1. BA画像と色・構成の方向性を確認する。
2. 優先: 初回案内、検索条件整理、コピー位置、解析後の編集中心化、本文優先の詳細をPC／モバイルの画面案へ反映する。
3. 追加案の採否を決める。特に一覧から直接コピー・日付補助・検索条件復元は個別に判断する。
4. 通常／空／エラー／送信中／フォーカスの仕様を揃え、#129の選定結果と共通仕様を確定する。
5. 明示的な実装指示後、#130の範囲を照合して実装計画を確定。DB・認証・新ライブラリの変更は前提にしない。
6. 実装→対象テスト→全体テスト→RuboCop→git diff→結果報告で停止。commit・push・PRは別指示を待つ。

## 8. 後続実装の想定ファイルと注意点

| ファイル群 | 想定する変更 |
|---|---|
| shared/header、layouts/application、application.css | B左ナビ、A配色、モバイル表示・現在地・アカウント領域。CSP/importmap維持 |
| home/top、cards/index | 利用開始、初回／検索0件の区別、条件開閉、一覧情報整理 |
| prompt_templates/index・show、clipboard_controller | クイックアクセスの表示条件、コピー位置。直接コピー案は別途採否判断 |
| cards/_ai_creation_form、shared/_card_creation_steps | 解析前後の表示切替、原文と解析時点表示の開閉、再解析の区別、入力保持 |
| cards/show、_review_schedule、_learning_metadata、_review_quiz_prompt | 本文優先、用途別の操作パネル。既存のmember actionとvalidation維持 |
| 関連Request/System Spec | 表示・フォーカス・フォーム・失敗時の入力保持・認可等の振る舞いを確認。CSS値をなぞるテストは作らない |

閉じた領域の入力をdisabledにして送信対象から外さない。エラー時は該当パネルを開く。
解析時点のMarkdown表示をライブプレビューと誤認させない。変更内容は保存後の詳細で確認する。
再解析は編集済みのタイトル／本文を原文由来の内容へ置き換える可能性があるため明示する。
カード・タグ・個人テンプレートのcurrent_userによる分離、Markdown無害化、CSRFを維持する。

## 9. 設計・実装後の確認項目

- PC1440px・モバイル390px、320px等の狭い幅で主要操作と本文が読めるか。
- 長い日本語・タグ・コード・表・200%文字拡大で、ページ全体が横へはみ出さないか。
- 初回作成と「すでにAI回答がある人」の両方が迷わず進めるか。
- キーボードのタブ順が視覚順と一致し、開閉・検索候補・送信後のフォーカスを扱えるか。
- コピー失敗や形式崩れ時にも手動で復帰できるか。
- 原文・表示プレビューを閉じたまま保存しても値を失わないか。
- 入力エラーが閉じたパネルの内側へ隠れないか。
- 次回復習日なし・過去日・不正理解度を保存せず、エラーから修正できるか。
- 検索条件を開閉しても条件・URL・解除操作を失わないか。
- 未ログイン・他ユーザーアクセス・危険なHTMLの既存保護を維持できているか。
- Console/CSPエラー、スマートフォン実機でのキーボードとスクロールを確認する。
- 操作回数だけでなく、初回タスクでの迷い・スクロール・エラーからの復帰を同じ架空データで比較する。

## 10. 今回の変更と停止点

今回の成果物はBA画像・本計画・生成プロンプトのみ。元のA/B/Cは保持。
アプリコード、DB、branch、commit、push、PRの変更なし。RSpec/RuboCopは未実行。
ユーザーが選んだのはB構成+A配色の方向性で、追加UX案やこのハイブリッド画像の最終承認ではない。
本計画を提示した時点で停止する。
