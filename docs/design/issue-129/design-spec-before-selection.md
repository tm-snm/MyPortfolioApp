# 共通部品・状態・導線の設計仕様（選定前）

これは#129の仕様案。全案へ展開可能なルールを示す。ユーザー選定後に確定する。
画像生成で崩れた文言・細部より本書の条件を優先する。アプリへの適用は#130。

## 1. デザインの共通原則

- 主役は「つまずきを残す・見つける・読み直す」。新機能は加えない。
- 1画面で強調する操作を絞る。作成画面は保存、一覧は検索と作成、詳細は本文と必要時の復習。
- 常にフォームを展開しておく代わりに、必要な補助操作を開いて使えるようにする。
- HTMLの並び順もモバイルの読み順に合わせる。PCだけCSSで補助操作を右へ配置可能。
- 既存ERB・Bootstrap・CSS・Stimulus・Turbo・importmapを維持する。

## 3. 文字・余白・形

| 項目 | 共通 | 案別の違い |
|---|---|---|
| 本文 | 16px、行高1.7。文章は目安44文字前後で折り返し | A/Bはsystem-ui系、Cのみ見出しに明朝系を候補 |
| フォント候補 | system-ui、-apple-system、BlinkMacSystemFont、Segoe UI、Hiragino Kaku Gothic ProN、Yu Gothic、Meiryo、sans-serif | C見出しはYu Mincho、Hiragino Mincho ProN、serif。利用可否と読みにくさを実機確認 |
| 見出し | ページPC28〜32px／モバイル24px、本文見出し20〜24px | Cは明朝・中太、A/Bはゴシック・太字 |
| 補足 | 原則14px以上。重要な状態を極端に小さい文字にしない | 全案共通 |
| 余白単位 | 4、8、12、16、24、32、48px | モバイル左右16px、PC主要領域の上限1120〜1200pxを目安 |
| 本文領域 | PCの長文は最大約720px、モバイルは可変 | Bはナビ・補助領域を引いても読み幅を確保 |
| 角丸 | 一律に全要素へ適用せず役割で分ける | Aカード12/ボタン8px、B8/6px、C4/4px |
| 影 | ボーダーと余白を優先 | Aごく薄い影、B必要な浮遊UIのみ、C原則なし |

| コード・表 | 内容単位で横スクロール可能にする。ページ全体の横はみ出しを避ける | 本文の読み順を維持 |

フォントの新規インストール・外部配信・Gem/npm追加は前提にしない。
200%文字拡大時は固定高さで文字を切らず、PCレイアウトから縦積みへ移行可能にする。

## 4. 共通部品

| 部品 | 通常時 | 状態・注意点 |
|---|---|---|
| 主ボタン | 主要色＋白文字。操作名を具体的に表示 | hover/activeで明度を変え、focusは外周リングを付ける |
| 副ボタン | 白または背景色＋主要色の文字・枠 | 主操作と同じ強さにしない |
| 危険操作 | 赤文字＋削除などの明示ラベル | アカウント削除はアカウント領域、カード削除は補助操作領域。既存確認を維持 |
| タグ | 穏やかな背景＋濃い文字。長文は折返す | 選択解除のラベルは「Dockerを選択から外す」等。候補選択と削除操作を区別 |
| 入力 | 常に可視ラベルを持つ。placeholderだけで説明しない | 無効時aria-invalidとエラーへのaria-describedbyを維持 |
| 状態 | 今日の復習を優先表示。理解度・重要度は文字中心 | 色以外に状態名。重要度「高」等の値だけで意味を伝えない |
| 折りたたみ | 「絞り込み」「復習を記録」「その他の操作」等の意味ある見出し | button+aria-expanded/controlsまたはdetails/summary。キーボードで開閉可能 |
| focus | 3px程度の外周リング、2〜3pxの間隔 | 白背景では#A34B00候補（対白5.89）。背景により二重リング等で視認性を確保。表示を消さない |
| flash | 成功・失敗の見出し/文言と閉じる操作 | 色だけに頼らず、既存の通知・エラー構造を維持 |

## 5. 状態一覧

| 状態 | 表示・動作 |
|---|---|
| 初回・カード0件 | 「まだカードがありません」「プロンプトを選ぶ」。検索条件を主役にしない |
| 検索0件 | 「条件に一致するカードが見つかりませんでした」「条件を解除」。初回状態と区別 |
| AI出力が空 | 「AIの出力を貼り付けてください」。欄を赤枠、フォーカス移動。保存しない |
| 必須項目不足 | エラー要約と該当欄を関連付ける。「タイトルを入力してください」。本文・タグを保持 |
| 形式崩れ | 元の全文を本文に残して編集できる。自動保存しない |
| 解析中 | 「解析中...」。保存・再解析など競合する送信操作を一時無効化 |
| 保存中 | 「保存中...」。入力値・formactionを失わず、二重送信を抑制 |
| コピー中 | 「コピー中...」とボタン無効化 |
| コピー成功 | 「コピーしました。外部AIへ貼り付けてください。」と次の操作へのリンク |
| コピー失敗 | 「自動コピーできませんでした。プロンプト本文を選択して手動でコピーしてください。」 |
| 履歴記録失敗 | コピー成功と履歴保存失敗を区別する。コピーそのものを失敗扱いしない |
| 検索候補 | 2文字以上・250ms待機・最大10件を維持。上下/Enter/Escape、日本語変換中に確定しない |
| 候補取得失敗 | 「候補を取得できませんでした。そのまま検索できます。」通常検索を継続できる |
| 保存成功 | 「カードを作成しました」→詳細へ。本文と未来のメモを読み始められる |
| フォーカス | Turbo解析後は結果見出し、入力エラー時はエラーへ。本文へのスキップリンクを維持 |

## 6. ナビゲーション

未ログイン: Recall Card→トップ、ログイン→既存ログイン、無料で始める→既存新規登録。Google認証は表示しない。
ログイン後: カード一覧、今日の復習、プロンプト、ダッシュボード、カードを作成。現在地は色に加え下線・位置・aria-current等で示す。
アカウント領域: アカウント削除・ログアウト。削除が通常のページ移動と同じ意味に見えないよう分離。
A/Cは横ヘッダー、BはPC左ナビ。モバイルはラベル付きメニューに集約し、閉じる操作と閉じた際のフォーカス先を設計する。
フッター: 利用規約・プライバシーポリシー・お問い合わせを維持する。画像で省略されても実装範囲から削除しない。

## 7. コア導線

1. テンプレート一覧で用途を選ぶ。初回は公式テンプレートを見つけやすくする。共通と個人の区別は維持。
2. 詳細でコピー。主操作は長い本文より前へ。全文の確認は開閉領域等で可能にする。
3. 外部AIへ移動し、整理した回答をコピー。Recall CardがAIを呼ぶように見せない。
4. 「AI回答を貼り付ける」へ戻り、既存new_from_aiで入力。
5. 「内容を確認」で既存preview_from_aiへPOST。DB保存なし。Turboで同一画面のai_card_builderを更新。
6. タイトル・本文・未来のメモ・タグを編集。原文・解析時点のMarkdown表示は開閉できる構成案。ライブプレビューは追加しない。
7. 「カードを保存」で既存createへPOST。失敗時は入力を保持し、成功時は詳細へ。
8. 詳細は本文・コード・表・未来のメモを先に読める。PCは補助操作を横へ、モバイルは本文後へ。
9. 「復習を記録」を開き、必須の次回復習日と任意の理解度を入力して「復習した」。日付なしの即時完了へ仕様を弱めない。
10. 一覧へ戻り検索・タグ・復習条件で再利用。条件を開閉しても選択値を失わず、GETのURLへ保持する。

## 8. 後続実装で守る技術的境界

- current_user.cards/tags、PromptTemplate.available_toと所有者限定更新を維持。
- CardParser、CardTagAssigner、既存transaction、Strong Parametersを変更する前提にしない。
- MarkdownのCommonmarker変換・sanitize、HTMLを保存しない方針を維持。
- routes・API・DB構造の追加なし。既存のmember actionとformactionを維持。
- clipboardの利用履歴POSTにCSRF tokenとsame-originを維持。
- ユーザー入力はエスケープし、候補・タグ生成でtextContent等の安全な扱いを維持。
- 既存CSPとimportmapのnonceを壊さず、新しいinline scriptや外部フォント依存を作らない。
- 画面文言変更でSpecが失敗しても、認可・validation・入力保持の保証を弱めない。
- テンプレート、ダッシュボード、認証、アカウント関連、公開情報ページへ上記共通部品を#130で展開する。

## 9. 確認と選定後の残作業

PC・実機スマートフォン、長い日本語・タグ・表・コード、200%拡大、キーボード、画面読み上げ、Console/CSPを確認する。
DB変更・Google認証・新Gem・npm・React/TypeScript導入はしない。
