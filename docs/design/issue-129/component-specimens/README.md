## 見本の構成

| 部品 | 通常 | エラー | 送信中 | フォーカス |
|---|---|---|---|---|
| ボタン | 主・副・危険操作 | エラー説明＋再操作 | 具体的な文言とdisabled | 3px青リング＋2px間隔 |
| フォーム | 可視ラベル＋補足 | 赤枠＋修正方法＋aria関連 | 入力値を保持したreadonlyの表示例 | 入力位置の青リング |
| タグ | 表示用／選択中と解除 | 保存失敗メッセージ、選択値保持 | 解除無効化、タグ保持 | 解除ボタンへフォーカス |

ボタンの「エラー」は操作失敗後の案内、タグの「エラー」は保存失敗の例。新しい入力制限・validationを定義したものではない。
上部のフォーカス列は比較用に輪郭を固定表示。下部では実際のTab移動も試せる。

## 操作して確認できること

1. タイトルを空にして「保存を試す」→入力欄のエラーとフォーカス。
2. タイトルと本文を入力して「保存を試す」→約3秒の送信中→見本内の確認完了。
3. 「保存失敗を表示」→値・選択中タグを保持して失敗表示へ。
4. タグ解除→残るタグまたは保存ボタンへフォーカスを移動。
5. 「見本をリセット」→架空の初期値へ戻す。

実際のカード保存・削除・通信は行わず、入力はページ内だけで扱う。
送信中にどの入力をロックするか等の実アプリの詳細仕様は#136/#143で確定する。本見本はその挙動の確定を意味しない。
ホバー／押下時の色もCSSに定義しているが、今回の操作確認は主に指定された4状態を対象とした。
